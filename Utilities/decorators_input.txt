Required input for the decorators and short explanation of behavior

User data accepted (two options):
- Dict form: {username: string, role: string}
  - Example: {"username": "alice", "role": "doctor"}
- Module session: Models.users.get_current_user() or Models.users.current_user
  - Should return either the dict above or an object with a .role attribute

Behavior of the decorators (short names used in code):
- login(func):
  - Ensures a user is present (from argument or session). If missing, prints
    "Access denied: please log in first." and stops the call.
- role(role_name_or_list)(func):
  - Ensures a user is present then checks the user's role (case-insensitive).
  - If role does not match allowed roles, prints
    "Access denied: insufficient permissions." and stops the call.

How to call functions protected by the decorators (examples):
- Pass a user dict as kwarg: protected(user={"username":"u","role":"doctor"})
- Pass a user dict as first positional arg: protected({"username":"u","role":"doctor"})
- Or set session: Models.users.login_user(...) then call protected() with no user arg

Notes:
- The extractor accepts a user object from the session API even if it is an object
  with attributes (object must be returned by Models.users.get_current_user()).
- If you prefer passing object instances directly to decorated functions, update
  the decorator extractor to accept object-like first positional args (optional).

Detailed, bit-by-bit explanation of the decorators code

1) Imports and typing
- "from functools import wraps": brings a helper that lets a decorator keep the
  original function's name and metadata. If this line is missing decorators will
  still work but wrapped functions will lose their original name and docstring.
- "from typing import Callable, Iterable, Optional": provides type hints used
  for readability. If removed nothing breaks at runtime; it's only for clarity.

2) Helper function `_get_user(args, kwargs)`
- Purpose: find the "current user" in several places so decorators can check it.
- Step A: look for a keyword argument named "user" or "current_user".
  - Input: `kwargs` from the wrapped function call.
  - Output: return that value immediately if present and truthy.
  - If this line is not present the decorator won't honor explicit `user=` calls.
- Step B: check first positional argument (`args[0]`) and accept it only if it
  is a dict containing "username" or "role".
  - Input: `args` from the wrapped function call.
  - Effect: allows calling protected functions like `f({'username':'u','role':'r'})`.
  - If this check is missing the decorator will not accept a dict passed positionally.
- Step C: try importing `Models.users` module.
  - If found, try to call `get_current_user()` if that callable exists.
  - If `get_current_user()` raises or is missing, try reading `Models.users.current_user`.
  - This allows session-style lookup: `Models.users` can supply the active user.
  - If this block is missing the decorator can't use the shared session object.
- Final: return the user object/dict or `None` if nothing found.

3) `login` decorator
- Purpose: block function execution unless a user is present.
- Operation:
  - Call `_get_user(args, kwargs)` to discover the user.
  - If `_get_user` returns a falsy value, print "Access denied: please log in first." and return None.
  - If user is present, call the original function with the original arguments.
- Input: any function; it reads call-time args/kwargs.
- If you remove the `print` line, denied calls will silently return None (less clear to users).

4) `role` decorator factory
- Purpose: allow functions only for specific role(s).
- Construction:
  - Accept either a string like "doctor" or an iterable like ["doctor","receptionist"].
  - Normalize to a lowercase set of allowed role strings.
- Wrapper behavior:
  - Call `_get_user(args, kwargs)` to discover the user.
  - If no user: same login-denied behavior as `login`.
  - If user exists, read the user's role value:
    - If the user is a dict: read `user.get('role')` or `user.get('role_name')`.
    - Otherwise assume an object and read attribute `user.role`.
  - Compare lowercase role to allowed roles; if not allowed print
    "Access denied: insufficient permissions." and stop.
  - If allowed, call the original function.
- If the role-reading lines are removed, the decorator can't tell what role the
  user has and will treat all users as unauthorized.

5) `__all__` setting
- Purpose: lists the names exported when doing `from Utilities.decorators import *`.
- If missing, importing `login` or `role` explicitly still works, but wildcard
  import behavior might change.

Examples of inputs each part expects
- `_get_user`: expects either a dict with keys `username` and `role`, or the
  `Models.users` module exposing `get_current_user()` or `current_user`.
- `login` decorator: no direct inputs beyond the wrapped function; it relies on `_get_user`.
- `role(...)` decorator: a role string or list at decoration time; at run time it
  relies on `_get_user` to produce the user and then expects `role` value in
  the retrieved user.

What to change if you want different behavior
- Accept object instances passed positionally: change the positional-check to
  accept objects with `.username` or `.role` attributes in addition to dicts.
- Auto-inject the discovered user into the wrapped function's first argument:
  modify wrappers to call `func(user, *args, **kwargs)` when `user` was found.
